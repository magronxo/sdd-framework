### SEED-08 — Provider connections contract (multi-provider connect)

**Short analysis**

- problem: afegir un provider nou és avui un acte ad-hoc sobre codi del proxy; no hi ha contracte estable
- overlaps: SEED-07 opera sobre providers (routing, budgets) però no defineix el contracte; SEED-07 depèn d'aquest contracte
- maturity: idea clara, destí "spec", Horizon NEXT — madura per entrar a disseny
- recommendation: triar ara (NEXT → disseny) perquè és precondició per al hardening del proxy

**TRIAGE (minimal contract)**

- problem: "afegir un provider nou" no té un contracte estable; depèn de codi hardcoded al proxy i d'un catàleg extern (OpenCode)
- objective: definir un contracte de Provider Connection que faci d'afegir un provider una operació incremental i verificable, no un canvi de codi arbitrari
- scope:
  - Schema mínim de provider (id, name, type, endpoint, auth_type, capabilities, models[])
  - Interfície de configuració (fitxer JSON) per registrar providers
  - Kernel i proxy llegeixen providers de configuració, no de codi
  - Contracte versionat (v1)
  - API per consultar providers disponibles (GET /api/v1/providers)
- non-scope:
  - Implementació de cap provider específic
  - Autodiscovery de models (SEED-07)
  - Rate limiting, budgets, routing (SEED-07)
  - UI de gestió de providers al dashboard
  - Modificació del client HTTP existent del proxy
- impact:
  - workflow: "afegir provider" passa de tocar codi a editar config
  - kernel + proxy: consumidors del contracte, sense providers hardcoded
  - dashboard: pot llegir llista de providers des de configuració
  - developer experience: operador o agent sap com afegir provider consultant config, no codi
- risks:
  - contracte massa rígid que no suporti nous tipus de provider
  - over-engineering amb camps que no es fan servir ara
  - dependència amb SEED-07: el contracte és layer més baix, SEED-07 el consumeix
- success signal:
  - Un provider nou s'afegeix editant configuració, sense tocar codi font
  - Kernel/proxy llegeixen de `agenticos_data/config/providers.json`
  - API disponible: GET /api/v1/providers
  - Contracte versionat (v1) i documentat

**DECOMPOSE**

- decision: 1 feature

- dependencies/order:
  1. feat-027 (aquest): Provider Connection Contract
  2. SEED-07 (futur): LLM Proxy Hardening — consumeix el contracte per a routing, fallbacks, budgets
